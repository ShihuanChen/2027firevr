## 2. 五节点流程

设计原则：每一步只给**该通道当时能给的信息**，不替玩家判断，不暗示正确答案。

| 节点 | 玩家可做 | 系统反馈 | 证据 / 设计边界 |
|---|---|---|---|
| **1 获知** | 在卧室醒来；环顾（门缝、窗、手机）、侧耳、起身 | 按实验条件只呈现一类线索：门缝渗烟 / 远处警报声 / 走廊喊叫 / 什么都没有 | 有火情且有人先察觉：报道（事实 2）。线索数量与类型：**实验变量**，非还原 |
| **2 确认** | 走到门口查看、开门一条缝、退回、看猫眼、拨打/接听 | 开门则烟气涌入、能见度骤降；关门则恢复；若条件为"有第二渠道"，此时出现一条**明示来源**的提示（邻居敲门声 + 门外人声 / 手机来电显示为楼下住户 / 楼栋广播） | 多通道确认是拟设计交互。报道只说"最先察觉"，未写她如何确认 |
| **3 告知** | 向阁楼喊话、上楼敲门、打电话、发消息 | 被通知者回一句简短确认（"知道了""我们上阳台"）；未通知则后续不出现该角色 | 报道有"告知老人与女孩"与"戴面罩等待"（事实 3、4）；具体话术为设计构造 |
| **4 行动** | 三个方向任选：① 走入户门 / 楼梯；② 留在房间关门堵缝、退到窗边或阳台；③ 翻窗到外墙/空调外机 | 选①：开门后 8–15 秒内能见度降到 1 m 以内，前进口被烟墙封住，系统不阻止，但持续给"退回"的可行动提示；选②：房间温度与烟密度缓慢上升，60 秒后进入"待援"状态；选③：进入高危分支，**系统立即提示风险并允许退回**，不给予任何进度奖励 | 通道失败与翻窗：报道（事实 5、6）。失败时间常数、烟密度曲线为设计参数，须消防专家审校 |
| **5 回顾** | 查看时间线：每条线索何时出现、自己在哪一步做了什么、哪些信息始终没拿到 | 并列显示"你获得的信息"与"当时客观存在但你未获得的信息"（后者仅在该条件组内显示） | 研究记录，不判定对错 |

**一处刻意的设计**：不把"翻窗"做成可选项之一并列呈现，而是玩家自己走到窗边才触发。原因是 S17 里翻窗是**通道全部失败之后的选择**，不是并列的最优解之一；若并列列出，会诱导玩家把它当成合理策略。

## 3. 三条路径对应的机制标注

| 路径 | 六轴对应 | 报道依据 |
|---|---|---|
| 老人 + 11 岁女孩：戴面罩退至 10 楼阳台 | D3 固守、C5 路径被烟封、E3 被外部指令（女事主叮嘱）替代判断、F2 + F3 | 事实 3、4、8 |
| 女事主：入户门→失败→翻窗→空调外机 | C6 路径归零、D5 非常规离楼、E1 自行判断 | 事实 5、6 |
| 丈夫：开门查看→关门→拆防盗网→楼梯间→撤离 | d1 线索驱动、C4（防盗网为需破拆的构件）、D5 转 D1、E1 | 事实 7 |

这三条不是三条分支剧情，而是**同一空间约束下的三种决策结果**。首版只让玩家扮演女事主视角（信息最全、决策最多），其余三人作为被通知者/环境角色。

## 4. 首版实验设计（只动一个变量）

| 项 | 设定 |
|---|---|
| 唯一自变量 | **是否存在可获得的第二确认渠道**（有 / 无） |
| 保持不变 | 火情起点与蔓延曲线、房间布局、可用出口、任务描述、总时长、线索出现时刻 |
| 因变量 | ① 正确识别已给出的信息（给了什么、何时给）② 首次行动前的确认行为次数与类型 ③ 决策理由（事后半结构访谈编码）④ NASA-TLX |
| 不测 | 共情。首版不设共情指标——共情是多维构念，未定义清楚前不测 |
| 样本 | 先 8–12 人可用性试跑（只答"看没看懂、找不找得到、卡在哪"），再决定是否做对照 |

**关于声音**：首版把警报声当作受控环境线索，不做第二个自变量。若后续要做"视觉/振动替代"，必须用不同组设计，且**不能靠给健听者静音来宣称模拟听障体验**——那只是降低信息量，不是经历听障。

## 5. MVP 开发清单（Unity 6 LTS + URP + XR Interaction Toolkit + OpenXR / Quest 3）

| 模块 | 内容 | 验收 |
|---|---|---|
| 场景 | 一室 + 阁楼 + 入户门 + 窗 + 阳台；楼梯段（仅用于路径失败判定） | 能走、能开门、能到窗边 |
| 烟与光 | 体积烟（体积雾 + 局部粒子）、门缝渗烟、能见度随开门骤降 | 开门 8–15 s 内能见度 <1 m |
| 线索 | 门缝烟 / 警报声（空间音频）/ 门外人声 / 手机来电；按条件开关 | 每个线索有独立触发与时间戳 |
| 可交互对象 | 入户门、窗、手机、面罩箱 | 抓取/推拉交互稳定，无穿透 |
| 记录 | 每次交互写 `{t, 对象, 动作, 位置, 朝向}` 到 JSONL | 能还原完整操作时间线 |
| 回顾界面 | 时间线 + 信息获得/未获得对照 | 玩家能读懂，不需口头解释 |
| 舒适与安全 | 瞬移 + 连续移动双选、视野收缩（vignette）、随时暂停退出、坐姿可玩 | 试跑无人报告眩晕中断 |
| 内容审查 | 烟密度曲线、可行动提示语、面罩使用说明 | 有资质消防专家签字 |

桌面版先做：同一套交互用键鼠跑通，跑完 8–12 人可用性，再迁移到 VR。理由：交互逻辑的问题在桌面就能暴露，不必每次戴头显。

## 6. 这个原型证明不了什么（写在设计文档里，不写在论文里当结论）

- 证明不了"信息确认能提升共情"。首版只测识别、行为与理由。
- 证明不了六轴设计空间"有效"。一个案例只能验一条路径。
- 证明不了"真实还原"。平面、时序、对白都是构造。
- 证明不了群体代表性。S17 是中国城市住宅、家庭结构完整、有培训与器材的一户，属语料里条件较好的一端。
