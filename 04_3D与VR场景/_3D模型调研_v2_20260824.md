# 文生3D / 场景还原 模型调研 v2（更新版）

> 基于 2026-08-20 `_3D模型调研.md` + 2026-08-24 补查。目标：为"新闻语料 → VR 3D 场景还原"选最适模型，并定义还原步骤与期望目标。
> 关键更新：**HY-World 2.0（混元世界模型）已能生成可漫游 3D 世界（场景级），填补了 8/20 调研中"只有单体物体、没有场景级"的缺口。**

---

## 一、推荐技术栈（按用途分层）

| 用途 | 首选模型 | 备选 | 理由 |
|---|---|---|---|
| **物体/资产级**（楼梯、轮椅、防火门、浓烟体、角色化身） | **Hunyuan3D 2.5 / 3.0**（开源权重 + 腾讯云国际站 API + 中文文档 + PBR + 自动绑定） | **TRELLIS.2**（MIT，质量天花板，需 24GB 本地或租云，给 hero 资产） | Hunyuan3D 有 API 可调、中文、PBR、产品线完整；TRELLIS.2 几何最精细但本地算力门槛高 |
| **场景/世界级**（整层楼梯间、外立面、可漫游空间） | **HY-World 2.0（混元世界模型 2.0）** | 暂无明显开源竞品（Genie 3 / HY-World 1.5 只出视频，不出可编辑 3D 文件） | 直接文字/图片/视频 → 可漫游 3D 世界（Mesh/3DGS），可导入 Unity/UE 二次编辑；开放申请体验 |
| **提质两阶段**（必用） | text → image（Seedream / 即梦 / SD）→ 3D | — | 直接文生3D 质量差，图生3D（先用概念图）质量显著更优 |

**一句话结论**：物体用 **Hunyuan3D**，场景外壳用 **HY-World 2.0**，两者都走"先出图再生3D"两阶段；TRELLIS.2 留给需要最高几何精度的个别 hero 资产。

---

## 二、还原步骤（pipeline：新闻素材 → 可漫游 3D 场景）

1. **素材解析**：取一条 S+/S 级新闻（如宏福苑），从 `SAVTBC` 六维标签 + `_VR场景重建蓝图.md` 提取场景元素（例：S=高层/楼梯间、A=85dB火警铃/听障、B=轮椅被门槛阻断、V=黑烟灌入、T=深夜快速蔓延）。
2. **拆解为生成单元**：场景骨架 + 若干物体资产 + 1–2 个角色化身（按蓝图 A1–A4 资产清单）。
3. **生成**：
   - HY-World 2.0 出场景外壳（高层单元 / 楼梯井 / 走廊）；
   - Hunyuan3D 出关键物体（轮椅、防火门、消火栓、浓烟体可选）；
   - 关键资产走 text→image(Seedream)→3D 两阶段提质。
4. **组装**：在 Unity / Unreal 拼接，套用蓝图里的 shader（下灌浓烟、低照度）、音频（空间化警笛/拍门）、交互参数（老年人步速×0.6、轮椅不可上台阶）。
5. **人工调优**：反复迭代（导师明确："可能不是一次生成，需要人工反复调"）——调提示词、补几何、修拓扑。
6. **验证**：在 VR 头显/编辑器中确认可行走、共情机制（限制模拟/感知剥夺）是否生效。

---

## 三、期望达到的目标（分级）

- **短期（pilot，当前阶段）**：选 3–5 条代表性新闻（覆盖蓝图 A1 楼梯间 / A2 外立面火 / A3 窗户逃生 / A4 设施缺陷），各产出 1 个**可漫游 3D 场景雏形**（空间还原 + 氛围，未必可交互）。截图/录屏作为论文 Figure 与 pilot 美术参考。
- **中期**：验证"新闻 → 3D 场景"管线可行性；确定主力模型 + 人工调优工作量（每条迭代几轮）；结论写入方法章节作为"scene generation module"证据。
- **长期（poster 核心贡献）**：这些场景成为 VR 系统的实际关卡素材，形成 **coding → design space → 3D 还原 → VR 体验** 完整故事线，支撑"设计系统 + 开发 + 3-5 人体验"的 poster 工作量门槛。

**明确不做（scope 边界）**：不是生产级精修资产、不是全 125 条生成、不是直接可玩 VR 关——仅是可行性验证与素材雏形。

## 四、诚实约束（必须提前知道）

1. **HY-World 2.0 需申请体验**（https://3d.hunyuan.tencent.com/sceneTo3D，GitHub: Tencent-Hunyuan/HY-World-2.0），不一定立即可用；Hunyuan3D 有腾讯云国际站免费额度（注册送额度）。
2. **本机无 GPU 算力**：本地跑 TRELLIS.2 需 ~24GB 显存、本地 Hunyuan3D 全量 ~29GB；需走 API 或租云（Vast.ai 等 ~0.5 美元/小时）。
3. **直接文生3D 质量差**，必须用 text→image→3D 两阶段。
4. 生成 mesh 通常仍需 retopology / 清理才能进引擎；算"第一稿 blockout"，非最终资产。
