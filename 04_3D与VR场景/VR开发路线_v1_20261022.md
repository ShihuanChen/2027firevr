# VR 开发路线 v1：从六轴到可跑场景

2026-10-22 ｜ 前置：设计空间 v3（六轴 34 档）、编码集 v4（103 事件 / 106 篇）
用途：回答三个问题，能还原到哪一步、用什么建、先建哪个

---

## 0. 结论先行

**能还原到「处境可辨识、机制可触发」，不能还原到「事故可复现」。**

新闻给的是认知条件与时序，不给户型图、材质、精确光照、精确时间。所以 VR 的还原对象是**决策结构**，空间只是承载。这条判断决定后面所有工程取舍：灰盒优先，精模靠后。

| 层级 | 内容 | 语料支撑 | 单人成本 | 进论文的形态 |
|---|---|---|---|---|
| L0 场景卡 | 平面拓扑 + 线索时序 + 可行动集 + 参数表（纸面） | 强 | 3 天 ×3 张 | Figure 与附录，本身就够 |
| L1 灰盒 | 体块、门、楼梯、走廊、可走可交互，无材质 | 强 | 1 周 | 视频素材 |
| L2 感官层 | 烟浓度与能见度衰减、空间音频、热感、低照度 | 中 | 1.5 周 | 被试体验的主载体 |
| L3 具身层 | 化身高与步速、蹲爬、推门、受限移动、呼吸与咳嗽 | 弱到中 | 1.5 周 | 机制成立的关键 |
| L4 他人层 | NPC 邻居、消防员、语音指令延迟与错误指令 | 弱 | 1 周 | 只在特定场景加 |
| L5 场景族 | 同一灰盒换参数生成 6–12 个处境 | 强（六轴组合） | 1 周（在 L1–L3 之后） | 系统性证据 |

**建议终点定在 L1 + L2 + 部分 L3 + L5，暂不做 L4 全量。** 理由：L3 之前是"能看"，L3 才是"能共情"；L4 的 NPC 是最贵最不可控的一环，只在一个场景里做一版即可。

## 2. 三必还原、三不还原

| 必还原 | 为什么 |
|---|---|
| 线索的通道、时刻、清晰度 | a 轴全部内容的物理形态。少一个通道，整个处境就变了 |
| 路径的状态与代价 | c 轴。路径不是"有/没有"，是"可用/要付出身体代价/进去会死/总数为零" |
| 身体条件对动作的过滤 | f 轴与 C3。同一个门，老年人与轮椅使用者面对的是两个不同的门 |

| 不还原 | 为什么 |
|---|---|
| 真实户型与真实建筑 | 语料不提供，硬做就是编造。用通用高层单元替代，并在论文里明写这是 design fiction 层 |
| 真实伤亡与遇难者形象 | 伦理红线。不出现遗体、不出现真实姓名、不做死亡特写 |
| 火场物理精度 | 流体与燃烧模拟对研究问题无贡献，成本极高。用叙事压缩（烟按曲线增长）替代 |

## 3. 技术选型

| 方案 | 优势 | 劣势 | 判断 |
|---|---|---|---|
| **Unity 6 LTS + XR Interaction Toolkit + OpenXR** | 参数化配置最顺（ScriptableObject / JSON）、Quest 一体机成熟、实验室设备与 EmbroidVR 经验可复用、日志与问卷集成方便 | 学习曲线、构建慢 | **主线** |
| WebXR（three.js / Babylon） | 免安装、远程被试、分享链接 | 性能与手势弱、presence 测量被质疑、音频空间化差 | 只做「远程低配版」备选，不并行开发 |
| Unreal 5 | 视觉最好 | 一体机性能吃紧、C++ 与蓝图双轨、迭代慢 | 不做。美术不是本研究变量 |

**设备**：Quest 3 一体机直出，不做 PC VR 串流。理由：一体机可带去访谈现场、被试无需学线缆、构建即部署。

**版本钉死**：Unity 6 LTS + URP + XR Interaction Toolkit 3.x + OpenXR Quest 支持包。URP 不用 HDRP，一体机跑不动。

## 4. 工程架构

### 4.1 目录

```
FireVR/
├─ Assets/
│  ├─ Scenes/            S1_IsolatedElderly / S2_NoWarning / S3_StairSmoke
│  ├─ Scripts/
│  │  ├─ Core/           ScenarioLoader, AxisConfig, TelemetryLogger
│  │  ├─ Perception/     CueChannel, CueScheduler, SensoryMasking
│  │  ├─ Action/         ExitStateMachine, BodyProfile, ActionGate
│  │  ├─ Social/         SocialCue, InstructionDirector, NpcBehavior
│  │  └─ UI/             FadeToBlack, ConsentGate, ExitAlways
│  ├─ Configs/           S1.json / S2.json / S3.json（六轴参数）
│  ├─ Prefabs/           Exit_Stair / Exit_Window / Door_Fire / Prop_Junk
│  ├─ Audio/             siren_far / knock / shout / fire_crackle / alarm_beep
│  └─ Materials/         smoke_fog, ember, emergency_light
└─ ProjectSettings/
```

### 4.2 五个系统，对应六轴

| 系统 | 对应轴 | 职责 |
|---|---|---|
| PerceptionSystem | a | 通道注册表：每通道有 enabled / clarity / masking 三态；线索按时刻投放 |
| SocialSystem | b、e | 谁在什么时刻提供了确认；指令可延迟、可错误 |
| ActionSystem | c、d | 出口状态机 + 可用动作集 + 动作代价 |
| BodySystem | f、C3 | 步速、视角高度、可交互范围、通道缺失、能否上下楼 |
| Telemetry | — | 位姿 10 Hz、交互日志、决策延迟、退出点 |

           {"t":90,"channel":"social_phone","id":"colleague_call","clarity":0.8}],
  "body": {"profile":"elderly","speed_scale":0.6,"eye_height":1.55,

### 4.4 六轴到引擎参数的映射（写论文时直接用这张表）

| 轴 | 档 | 引擎开关 |
|---|---|---|
| a | A1 多通道 / A2 单通道 / A3 构件挡视线 / A4 警报日常化 / A5 无信号 | CueChannel 的启用集合与 clarity 曲线；A3 加遮挡物；A4 给同一通道加"重复误报"历史 |
| b | B1 独自察觉 / B2 具体的人 / B3 渠道 / B4 中介转述 / B5 无人告知 | SocialCue 的事件类型（人声/消息/广播）与是否有具名来源 |
| c | C1 全通 / C2 单一 / C3 身体不足 / C4 外力封闭 / C5 充烟 / C6 全断 | ExitStateMachine 的状态与转换条件；C3 由 BodyProfile 否决而非出口本身 |
| d | D1 向下 / D2 向上 / D3 固守 / D4 跨户 / D5 非常规 | ActionGate 的可用动作集与风险标签 |

## 5. 先做哪三个场景

选这三条不是随机，是覆盖分布最密与最稀两端：A5+A2 占 59%，C6 占 30%，D5 占 18%；同时各带一个稀有档，保证机制跨度。

| 场景 | 对应事件 | 六轴组合 | 目标机制 | 空间 |
|---|---|---|---|---|
| **S1 封窗的独居老人** | E0167 宏福苑赵姨 | A3 A4 / B2 B4 / C6 / D3 D5 / E1 / F2 F8 | 感知被构件阻断后，靠声音、电视、电话三层间接确认；路径归零后只能在室内等待与窗口示意 | 单走廊 12 层一户，南窗被发泡胶板封死 |
| **S2 无人告知** | E0810 马鞍山 | A5 / B5 / C5 C6 / D3 / E1 / F1 | 没有任何信号，救援敲门也听不见；玩家必须自行发现或错过 | 同灰盒，去掉全部社会线索 |
| **S3 楼梯即危险** | E0001 类 | A2 / B1 / C5 / D1 D5 / E1 E2 / F1 F4 | 楼梯可走但进去会死，判断"能走"与"该走"的分离 | 楼梯井充烟，能见度随下降衰减 |

S1 与 S2 共用灰盒，只换 JSON，这是最快证明"参数化成立"的方式。S3 需要楼梯井，单独做一次。

## 6. 分阶段路线

| 阶段 | 目标 | 产出 | 验收标准 | 工时 |
|---|---|---|---|---|
| **P0 场景卡** | 不写代码，先把三张卡钉死 | 三张场景卡（JSON 草案 + 平面图 + 线索时序图） | 每个档位都能指到语料出处；任意一张卡别人能照着搭出来 | 3 天 |
| **P1 一个可走的灰盒** | S1 能从头走到尾 | Unity 工程 + Quest 构建 | 走完 300 秒流程；日志落盘；中途可随时退出；帧率稳定 72 | 1 周 |
| **P2 参数化** | 同一灰盒变三个处境 | S1/S2/S3 三份 JSON + 加载器 | 只改 JSON 不改代码，六轴档位可见地改变体验 | 1 周 |
| **P3 感官与身体** | 机制开始成立 | 烟体、能见度、空间音频、步速、蹲爬 | 蒙眼测：只听声音能否判断危险来源方向；老年步速下无法在烟满前到达楼梯 | 1.5 周 |
| **P4 被试 pilot** | 6–8 人定性 | 问卷 + 日志 + 访谈提纲 | 能说出"哪一刻意识到不对"；能复述自己为什么选了那个动作 | 1 周 |

关键路径是 P1。P1 延期就砍 P4 人数，不砍 P1 的日志系统，因为过程证据是论文里唯一 VR 侧能出的数据。

### 每阶段与论文的接口

| 阶段 | 论文里对应 |
|---|---|
| P0 | Figure 4「六轴到场景参数的映射」，附录给三张场景卡 |
| P1–P2 | Video figure 与场景截图；方法章「design instantiation」一节 |
| P3 | 机制成立性论证（不需要被试也能写，靠设计论证 + 录屏） |
| P4 | 小样本定性发现，写进 Discussion，不承担主结论 |

## 7. 测量与日志

| 类别 | 指标 | 采集方式 |
|---|---|---|
| 行为 | 首次察觉时刻、首次行动时刻、决策延迟、路径选择、停留点、回退次数 | 引擎日志 |
| 生理替代 | 无（不做眼动与皮电，成本与伦理都不划算） | — |
| 主观 | presence（IPQ 或 SUS 式短版）、embodiment 3 题、NASA-TLX、SSQ（晕动） | 结束后纸笔或平板 |
| 定性 | 「哪一刻你觉得必须走了」「为什么没走楼梯」 | 半结构化访谈 15 分钟 |

SSQ 必做。楼梯 + 连续移动是晕动高发组合，P1 就要测，不能等到 P4。

## 8. 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| 晕动 | 被试 5 分钟内要求停止 | snap turn + 隧道视野 + 楼梯用高度插值不做物理攀爬 + 默认瞬移 |
| 性能 | 烟粒子一多就掉帧 | 屏幕后处理做能见度衰减，不用体积雾；粒子数上限 2000；draw call < 150 |
| 资产 | 全部门窗家具都要建模 | 只用 12 个通用件（门、窗、楼梯段、扶手、消火栓、应急灯、杂物堆、床、桌、电视、电话、阳台栏），全部灰盒 |
| 伦理 | 真实灾难再现引发不适 | 开场知情同意页、随时按键退出、不出现遗体与真实姓名、场景标注为「基于公开报道的重构」、被试可跳过任一场景 |
| 范围 | 想做六角色六场景 | 只做 F1/F2/F4 三种身体，F6 用通道缺失模拟而非视觉化身 |
| 时间 | 单人开发 | 砍 P4 人数、砍 L4 NPC，不砍 P1 |

## 9. 七天动作清单

| 天 | 动作 | 完成标志 |
|---|---|---|
| 1 | 装 Unity 6 LTS + URP + XR Interaction Toolkit，跑通官方 XR 样例到 Quest | 头显里能看见自己两只手 |
| 2 | 写 `AxisConfig` 与 `ScenarioLoader`，先只支持 space 与 cues | 改 JSON 能换出口与线索时刻 |
| 3 | 搭 12 件通用灰盒，做一段走廊 + 楼梯 + 一户 | 能走通，无穿模 |
| 4 | 写 `PerceptionSystem` 与 `Telemetry` | 日志能落 CSV：时刻、头姿、事件 |
| 5 | 填 S1 的 JSON，做封窗、烟雾衰减、空间音频三条 | S1 能走完，退出键有效 |
| 6 | S2 复用灰盒，只改 JSON（去掉全部社会线索） | 两场景共存，不改代码 |
| 7 | 自测一轮 + SSQ + 录屏 | 有一段可给老师看的 90 秒录屏 |

七天能给出的最低可交付：**一段 90 秒录屏 + 两份 JSON + 一张映射表**。这已经足够支撑「设计空间可操作化」这句话，也是老师最能看懂的东西。

## 10. 待定与需要外部输入

1. 头显型号与数量：实验室现有几台、是否可外借。决定 P4 能否并行跑。
2. 伦理审查：本校 IRB 流程与周期。P1 期间就应提交，不要等 P4。
3. 六角色化身是否要做：图形学上不难，难在"身体表征改变是否影响判断"，这会变成一个独立研究问题，建议本轮不做，只在 limitation 里提。
4. 是否需要远程版（WebGL）：若有外地被试需求才做，否则不做。
