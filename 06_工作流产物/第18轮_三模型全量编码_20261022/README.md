## 2　与 v4 提示词的四处差异

1. **删掉**「F5、F6 在现有语料中为零，不要为了填满而误标」。这句是结果引导，会让模型主动回避 F5/F6。
2. **新增**「正文可能因长度限制在 2000 字处截断，截断是采集限制不是叙事缺陷」。避免把截断判成低置信。
3. 全部 106 篇（103 起事件）一次跑完，不再只跑 60 条。
4. 落盘记录 `model` / 时间 / `usage` / 原始返回 / `invalid` 字段，任何一格可回溯。

其余判定线、示例、输出格式完全沿用 `05_编码包/提示词与交付_v4_单条.md`。

`run_models.py` 的行为：

- 并发 4。上到 6 时中转站返回 503 `model_not_found`，降到 4 稳定。
- 失败重试 3 次，退避 5/11/17 秒。
- **六轴全空判失败**并重试，不允许写入 `[]` 当结果。例外见下条。
- 只跳过 `ok=true` 的条目，失败条目下次重跑会补。

### 已知的合法失败

`E0008-1`、`E0054-1`、`E0265-1` 等属于 `off_axis=有` 的体裁（官方声明、司法追责、电视口播），六轴本来就该为空。当前脚本会把它们判成 `axis-empty`。

处理方式：跑完后对这三类单独放行，判定条件改为「`off_axis=有` 且六轴全空」时通过，其余全空仍判失败。

## 6　判读规则（先定好，避免看到数字再找理由）

| 指标 | 门槛 | 不达标怎么办 |
|---|---|---|
| Fleiss κ（轴级） | ≥ 0.6 可写进论文；0.4–0.6 作初标 | < 0.4 回读分歧证据句，定位是定义污染、主体不清还是样本稀有 |
| PABAK（逐档） | ≥ 0.7 视为该档可用 | 低于 0.7 且命中 ≥ 5 篇，说明判定线真的不清楚 |
| 命中篇数 | < 3 篇的档不报 κ | 只报频次与实例，说明该档稀有 |
| 六轴全空率 | 0（`off_axis=有` 除外） | 出现即判该条失败重跑 |

三条一起看。单看 κ 会把稀有档误判成不可靠（prevalence problem），单看 PABAK 会把「几乎全不标」的档当成高度一致。

## 8　这一轮实际发生了什么（三次中断，写清楚免得下次重踩）

| # | 中断 | 表现 | 处理 | 代价 |
|---|---|---|---|---|
| 1 | `norm()` 漏写 `out['id']` | 108 条结果没有主键，无法与切片对应 | 写 `recover_ids.py`，用 `evidence.quote` 在 106 篇正文里做唯一子串匹配，恢复 199／214（93%）；未命中的丢弃 | 重跑一次 |
| 2 | `off_axis` 定义写"某段内容装不进" | 模型标"有"的比例 89%，人工基准是 11.3% | 改为整篇判断 + 五类枚举（伤亡通报／司法追责／纯科普／灾后追访／演播室口播）+ 硬校验（说不出类就强制"无"）；并明确 off_axis 与六轴不互斥 | 这批数据的 off_axis 字段作废 |
| 3 | 中转站出口被封 | 后段全部返回 `403 region_restricted`，五个模型无一可用 | 未能解决，留在补跑清单 | 三模型全量没跑完，实际交付 78 条双模型 |

三条里第 1 条是纯粹的编程疏忽（写完 `rec['id']=sid` 却忘了把 `sid` 放进返回的 `out`），第 2 条是判定线措辞问题，第 3 条是外部依赖。

### 经验

- 跑批脚本先跑 3 条、检查落盘字段，再放全量。这次 318 次调用跑完才发现没 id。
- 任何"允许判无"的字段，都要给**穷举的类别清单 + 硬校验**，否则模型会用它表达"某段看不懂"，而不是表达"整篇不属于"。
- 外部 API 的可用性要提前试，不要假定能跑满 318 次。
