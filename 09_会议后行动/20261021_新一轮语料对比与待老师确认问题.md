# 新一轮语料对比与待老师确认问题

日期：2026-10-21  
输入文件：`recommended_id_chinese_body.csv`、`recommended_complete.csv`

## 一、两份文件的关系

两份文件包含相同的 20 个 `record_id`，ID 集合完全一致，中文正文逐条完全一致，正文长度也一致。因此它们不是两批不同新闻，而是同一批推荐结果的两种导出视图：

- `recommended_id_chinese_body.csv`：保留 `record_id` 和中文正文，但导出时产生了 7 个 `Unnamed` 列。这些列不是可靠的字段，疑似正文中的逗号、换行或表格残留造成的错位，后续不应作为标注字段使用。
- `recommended_complete.csv`：包含标题、原文、中文正文、URL、来源、日期和 `text_unavailable`，适合作为后续人工开放编码的工作底表。

20 条记录的正文均非空，`text_unavailable` 均为“否”。所以这批记录目前可以进入人工开放编码，但不能据此认为元数据完整：20 条中只有 1 条有明确发布日期，多个条目的 URL、来源或日期缺失。

## 二、初步质量检查

| 检查项 | 结果 | 处理建议 |
|---|---:|---|
| 记录数 | 20 | 保留为新一轮候选补充集 |
| `record_id` 唯一性 | 20/20 唯一 | 可作为主键 |
| 两文件 ID 是否一致 | 是 | 不需要合并成 40 条 |
| 中文正文是否一致 | 20/20 一致 | 以 complete 版为正文来源 |
| 正文是否为空 | 0 条为空 | 可进入人工开放编码 |
| `text_unavailable` | 20 条均为“否” | 可开放编码，但仍需来源核验 |
| 明确来源 URL | 12 条有 URL，另有多条缺失 | 补做 source registry |
| 明确发布日期 | 1 条明确，其他为“Base 未收录” | 不用于时间趋势分析，先补日期 |
| 重复新闻风险 | 有同一事件的多篇报道风险 | 以事件 ID/事件簇去重，不能只按标题去重 |

当前最明显的问题不是正文不可用，而是可追溯性不足：若把这 20 条直接并入主数据集，会把“正文可读”误当成“来源、时间和事件身份均已确认”。

## 三、建议的合并规则

1. 把 `recommended_complete.csv` 作为唯一工作底表；`recommended_id_chinese_body.csv` 只作为正文对照备份。
2. 先按 `record_id` 去重，再按“事件地点 + 事件日期 + 建筑/伤亡描述”建立事件簇，检查同一火灾的多篇报道。
3. 对 URL 缺失的记录保留正文，但将 `source_status` 标为 `missing`，将 `date_status` 标为 `missing`，不得填入推测日期。
4. 对来源聚合页、转载页或新闻摘要页，记录原始页面与转载页面的关系；正文可用于场景编码，来源等级需单独标注。
5. 只有在完成来源、日期和事件簇核验后，才把记录纳入用于频次统计的主分析集。开放编码可以先行。

## 四、社交媒体视频能否用于 VR 重建

可以使用，但应把它定义为“辅助观察证据”或“视觉参考素材”，不能直接当作新闻正文同等级的事实证据，也不能未经核验直接把视频画面还原成 VR 的确定空间结构。

适合使用的情况：

- 视频能确认烟雾方向、火焰蔓延、能见度、拥挤、救援动作、警报替代线索等动态现象；
- 视频有清晰的发布时间、拍摄地点、上传者或原始出处，并能与新闻报道或官方信息交叉验证；
- 使用目的是补充“可观察到的现象”和“时间变化”，而不是推断不可见的楼层结构、人物身份或完整因果链。

不宜直接使用的情况：

- 来源、时间、地点无法核验，或视频明显是转载、剪辑、拼接；
- 只凭画面猜测建筑尺寸、楼层、火源和人员状态；
- 把视频中的戏剧化片段直接转成共情刺激或交互机制；
- 将同一视频同时当作新闻证据、设计依据和实验刺激，造成证据与结果循环。

## 五、如何接入现有管线而不扰乱方法

建议增加一个独立的“视频证据层”，不改动新闻语料的主编码流程：

`新闻记录 → 视频候选登记 → 来源/时间/地点核验 → 视频观察编码 → 与新闻标签交叉验证 → 设计空间映射 → VR 原型`

视频层至少记录：`video_id`、关联 `record_id`、原始 URL、平台、上传者、发布时间、拍摄地点、是否原始上传、可观察片段的起止时间、观察标签、核验来源、授权/使用状态、置信度。

视频观察编码应只写“看到了什么”，例如“烟雾从走廊上方向下扩散”“楼外立面出现连续火焰”“人群在入口处聚集”；“因此楼梯间一定有烟囱效应”属于解释，应放在单独的推断字段并标低置信度。

设计阶段只把经过交叉验证的稳定特征转成 VR 参数。单个视频只能作为概念参考或待验证线索；至少两类独立证据一致时，才适合进入设计空间的证据栏。若视频只是为了制作气氛，可作为美术参考，不纳入新闻事实统计。

## 六、需要向老师确认的问题

1. 这 20 条是否作为“补充候选集”进入开放编码，还是必须先完成 URL、来源和日期补全后才进入主数据集？
2. 同一火灾的多篇报道是否保留为独立文本单元，还是按事件簇合并后只保留一条主记录？
3. 正文可读但来源和日期缺失的记录，能否用于设计空间的定性证据，且不进入频次统计？
4. 社交媒体视频是否允许作为 VR 场景的辅助证据？如果允许，老师是否要求建立单独的视频证据表和来源分级？
5. 视频证据进入设计空间时，最低核验标准是什么：单一可追溯视频即可，还是必须与新闻、官方通报或第二个独立视频交叉验证？
6. 视频画面用于原型、论文截图或实验刺激时，是否需要获得授权、模糊人脸和去除可识别地点？
7. 对视频无法确认的建筑结构，是否统一使用“通用高层模块”表达，避免把推测结构写成事件事实？
8. 这批新数据是否需要与现有 124/125 条主保留集重新计算一致性系数，还是仅作为补充材料单独编码？

## 七、当前建议

先把 20 条记录作为“可开放编码、待元数据核验”的补充集保存；暂不并入主统计集。社交媒体视频可以进入项目，但应作为独立的视频证据层，先登记、核验、观察编码，再决定是否映射为 VR 参数。这样既能利用视频提供的动态信息，也不会改变新闻语料、双人标注和设计空间证据链的基本管线。
