## 阶段一：一次性全量筛选（已废弃，v0-v5）

### v0: 标题级评分（最初）

**方法**：基于6维评分规则（fire+2, building+2, evacuation+2, population+3, length+1, exclude-5），从 8,072 条唯一 URL 中分出 Keep(52) + Pending(280) + Eliminate(7,740)。

**问题**：标题级评分无法判断正文质量，且51条 Keep 不足以下游使用。

### v1: 103条金标准 + AI启发式

**方法**：标注 103 条金标准（8保留+3半保留+92剔除），从中归纳关键词启发式 `predict(text)`。采用"保守自动剔除 + 不确定性路由"——永不自动保留，只对高置信剔除自动落定。结果：7,168 条自动剔除(87.6%)，1,004 条路由人工(12.3%)，8 条保留。

**价值**：这一轮形成了"具身场景可重建性"的筛选方法论论文稿（见 docs/人机协作筛选_方法贡献记录.md）。但其输出（1,004 条待复核）仍然太大，无法人工处理。

### v2-v5: 规则迭代

v2 加入 fire+building 主题预过滤 → 279保留 / 1,285待复核
v3 改为标题+开头联合匹配 → 167保留 / 216待复核
v4 标题事件正则（排除战争/政策/行业）→ 68保留 / 83待复核
v5 放宽场景+第一人称奖励 → 89保留 / 62待复核

**问题**：规则越加越复杂，但关键词始终无法可靠区分"有细节的报道"和"流程性报道"——同一场景词数的文章（如均含"smoke trapped firefighter"）可能一侧用户判保留、另一侧判剔除。这是关键词方法的根本限制。

**转折**：用户要求改为小批量迭代模式，每次以用户判断驱动规则进化。

## 阶段二：小批量迭代（当前，batch-1 开始）

### batch-1: 第1-100条

**筛选方法**：v4风格的标题事件正则 + 场景词检查，但没有使用用户判断。

**批次结果**：100条 → 候选保留17 + 待复核23 + 剔除60

**用户判后**：保留7条 + 剔除20条（73条未判，用户抽查）。首次人工金标准建立。

| 用户保留原因 | 用户剔除原因 |
|:---|:---|
| 细节较为丰富(2条) | 是政策/是外部过程描写(2条) |
| 部分场景细节(1条) | 没有/无细节描写(6条) |
| 人物动作细节丰富(1条) | 过程/过程和原因(4条) |
| 弱势群体提及(1条) | 细节描写不够(3条) |
| 可借鉴(1条) | 无场景相关(1条) |

**学到规则**：① 弱势群体词加分（用户看重）② 消防行业/机构标题排除 ③ 过程词太多扣分

### batch-2: 第101-200条

**筛选方法**：应用 batch-1 学到的规则——加入 industry 排除模式、场景/过程比例评分。

**批次结果**：100条 → 候选保留9 + 待复核8 + 剔除83

**用户判后**：保留4条 + 剔除18条（共22条判完）

**学到规则**：① 场景/过程比例（ratio）比原始场景词数更有效 ② 短报道(<1500字)且无场景词的直接剔除 ③ 用户更看重"有没有人物描写"而非"有没有火灾词"

### batch-3: 主动聚类学习（当前）

**方法切换**：顺序处理走到200条后，意识到每100条才产出~20条用户判断，效率太低。改为**主动聚类**：
1. 对所有未处理文章提取特征（场景词/人物词/过程词/弱势群体/长度）
2. 按特征向量聚成 ~60个类
3. 每类挑1条代表给用户判
4. 一个类别标完→整类自动处理

**问题**：第一版用了严格的火灾事件正则过滤，导致只有745篇文章进入聚类，用户质疑这数字太少。确实，火灾事件正则可能漏掉不少有效文章（如非标准标题格式的火灾报道）。修正：去掉严格火灾过滤，让全部文章进入聚类，用户自然区分。

## 阶段三：修正版主动学习（本次采用）

### 核心方法

仍保留的排除：战争/政治/体育/娱乐/消防行业/政策文件（这些用户已在batch-1/2中反复确认）
去掉的排除：火灾事件正则匹配（不再用正则判断"是否火灾"，交给用户判断）

### 聚类特征

每篇文章提取：场景词数(S)、人物引用词数(P)、过程词数(C)、弱势群体有无(VG)、长度段(L)
聚类key = 长度段_场景级_人物级_过程级_弱势级（如 `L_HYLN` = 长文_高场景_有人物_低过程_无弱势）

### 批次节奏

```
batch-1:   1-100   → 用户判27条 → 学到规则版本1
batch-2: 101-200   → 用户判22条 → 学到规则版本2
batch-3: 全部剩余(聚类代表) → 用户判~50条 → 学到规则版本3+覆盖全部聚类
batch-4: 自动处理剩余所有 → 用户0条(仅抽查)
```

总用户判断量：~100条，覆盖全部8180条。

## 阶段四：ML 聚类版（7.25，已验证并弃用传播逻辑）

### 实现与工具

`工作流/_ml_pipeline.py`，工具链：**pandas 3.0.5 + scikit-learn 1.9.0（系统 Python 3.11）**。
- TF-IDF 向量化（max_features=5000, ngram_range=1-3, 标题+正文前1000字）
- KMeans 聚类，k=15~50 用 silhouette 选优 → 最优 k=50, **silhouette=0.18**
- 已有标注的聚类按多数决自动处理；未标注聚类每类挑"距质心最近"1 条代表给用户

### 产物

- `工作流/_用户_ml版.csv`（47 条聚类代表，**待人工判断**）
- `工作流/_自动_ml版.csv`（3117 条自动处理：保留+剔除）

### 2026-08-02 严谨性审查结论（与朱倩讨论后）

**发现的问题**（不推翻工具，推翻"传播"逻辑）：
1. **silhouette=0.18 聚类结构极弱**（<0.25 接近随机）——"同类判断一致"假设不成立，代表判断传播=系统性错误扩散
2. **代表=距质心最近** = 最典型的文章，而非决策边界——人工最有价值的判断机会被浪费（正解是 uncertainty sampling，见 Settles 2009）
3. **传播零验证**：自动剔除 3117 条无抽样复核，误删率未知；与"保留集零污染"的贡献主张矛盾

**人工判断真实分布核实**（2026-08-02 读文件确认）：
- GoldSet 103 条（7.15，8 保留 + 3 半保留 + 92 剔除）
- batch-1 已判 27 条（7 保留 + 20 剔除）
- batch-2 已判 18 条（4 保留 + 14 剔除，4 条未填）
- **合计 ≈ 148 条**；batch-3A/3B（67 条）、第3轮112条、ml 版 47 条 **均未填**

**决策**：弃用"1 条代表传播整类"，改用 **committee 分歧度 = 不确定性采样**（保留工具：sklearn/pandas/GLM API；更换采样策略）：
- 三个评审投票：① v1 关键词启发式 ② 长度/结构启发式 ③ 弱势群体×人物叙事（可选第 4 票：GLM 五维语义评分）
- 分歧度高的条目优先路由给人（边界样本）
- 高置信剔除自动落定（沿用 v1 保守自动剔除，有 103 金标准验证）
- 每轮在金标准上报告 P/R/F1；保留集人工确认、剔除集抽样 5-10% 复核
- 可行性已验证（2026-08-02）：读数据 0.6s、TF-IDF 0.9s、KMeans 各 k 0.1-3.3s，全量 7,017 条 1-2 分钟可跑
