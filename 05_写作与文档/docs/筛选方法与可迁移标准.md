# 新闻正文筛选方法：从大规模采集到VR可重建语料

> 本文档详细说明从 8,180 条原始新闻正文中筛选出 151 条 VR 可用正文的方法学流程。这套方法设计为**可迁移的通用协议**，不依赖具体领域知识，可直接用于其他需要从大规模噪声语料中提取高质量叙事素材的场景。

**论文标签**：Data Curation · Human-AI Collaborative Screening · Embodied-Scene Reconstructability · PRISMA

---

## 一、问题定义

### 1.1 核心挑战

给定 N 条通过关键词检索获得的新闻正文（含标题、URL、全文），从中筛选出 M 条用于 VR 场景重建的优质素材。面临的难点是：

| 挑战 | 现象 | 比例(本数据) |
|:---|:---|---:|
| 主题不相关 | 检索词的语义歧义：wildfire/gunfire/fire sale/under fire 等 | ~52% |
| 非住宅火灾 | 工厂/仓库/商业建筑火灾，不是人类居住环境 | ~18% |
| 正文缺失或过短 | 付费墙、404、或简讯（< 400 字无叙事价值） | ~14% |
| 信息稀薄 | 仅有"X地火灾，Y人伤亡，原因调查中"，无可重建细节 | ~8% |
| 重复/镜像 | 同一通讯社稿件被数十个地方台转载 | ~4% |
| 其他(战争/政策/房价) | 标题含"fire"但实际内容为战争报道/行业政策/房地产广告 | ~4% |

最终只有约 2% 的原始语料具备 VR 场景重建潜力。

### 1.2 核心筛选原则：具身场景可重建性（Embodied-Scene Reconstructability）

筛选的唯一标准：**一篇新闻正文是否包含足够的空间/感官/身体动作/情感细节，使得 VR 设计师可以据此重建出一个可被第一人称体验的具身场景。**

这一原则派生自 Kilteni 等人对具身感（Sense of Embodiment, SoE）的三要素定义：

| SoE 要素 | 所需正文内容 | 具体例子 |
|:---|:---|:---|
| 自我定位（Self-Location） | 空间细节 | "起火点位于14楼卧室，浓烟沿楼梯间向上扩散至18楼" |
| 身体所有权（Body Ownership） | 身体动作 | "她扶着墙一步步往下挪，每走三层就停下来大口喘气" |
| 能动性（Agency） | 决策/行为 | "他决定不坐电梯，改走消防通道，但防火门被锁住了" |

## 二、数据采集（预处理阶段）

### 2.1 检索策略（PRISMA S0）

采用**概念块 AND 组合**策略构建检索式：

```
Block 1 事件: (fire OR blaze OR inferno OR "caught fire")
Block 2 场所: ("high-rise" OR "high rise" OR highrise OR tower OR "apartment building")
Block 3 疏散: (evacuation OR evacuate OR escape OR trapped OR rescue)
Tier-A: Fire AND Building [AND Evac]  (广召回)
Tier-B: + elderly OR disabled OR wheelchair OR deaf OR blind (弱势群体定向)
```

数据源：GDELT DOC 2.0（21检索式×24月）+ Google News RSS（8式）+ Bing News（8式）

**通用性**：此检索策略可以替换为任意领域的领域概念块 + 场景词块 + 人群词块。

### 2.2 去重（PRISMA S1）

**标准化去重规则**：
1. URL 标准化：去除 utm_*, fbclid, gclid, ref, src 等追踪参数
2. 协议统一：http/https
3. 去重依据：标准化后的完整 URL + 标题前 80 字符 + 正文前 200 字符的哈希签名
4. 保留规则：同一事件的镜像源，保留正文最长的版本

### 2.3 正文抓取（PRISMA S2）

三级兜底策略：
1. **trafilatura**（首选）：高质量正文提取，自动过滤导航/广告/评论
2. **requests + lxml**（回退）：去除 script/style/nav/footer/header 标签，提取 `<p>` 文本
3. **Playwright headless**（兜底）：JS 渲染页面，模拟人类滚动，注入反爬脚本

## 三、人工金标准构建（Stage A）

### 3.1 金标准规模

从全量语料中随机抽取 **103 条**，由领域专家逐条阅读全文，按标准标注：

| 标签 | 含义 | 数量 | 占比 | 标注依据 |
|:---|:---|---:|---:|:---|
| 1 | 保留 | 8 | 7.8% | 含可VR重建的具身场景细节 |
| 0.5 | 半保留 | 3 | 2.9% | 有一点场景但不清楚/边界案例 |
| 0 | 剔除 | 92 | 89.3% | 缺可重建细节/仅事实/仅过程/仅外部/完全无关 |

**关键观察**：89.3% 的高剔除率说明噪声极大，81.6% 的语料不具备叙事价值。

### 3.2 人类判断的具体标准（论文可引用）

人类标注者遵循的判定原则可归纳为以下 7 类去除原因：

| 去除原因 | 含义 | 金标准中占比 | 典型例子 |
|:---|:---|---:|---:|
| 无场景细节 | 仅事实罗列，无空间/感官描写 | 高频 | "某公寓火灾，X人受伤，原因调查中" |
| 仅过程/客观 | 只有经过、措施、原因结果 | 中频 | "消防队赶到→灭火→送医→调查" |
| 仅对话/经历 | 有人物经历但无场景 | 低频 | 幸存者采访但只谈心理感受 |
| 仅灾后/外部 | 只描写结果或外部视角 | 低频 | "建筑外墙被烧黑，窗户破碎" |
| 完全无关 | 基建/房地产/政策/行业 | 中频 | "消防部门开展高层建筑隐患排查" |
| 仅措施 | 只讲了解决措施 | 低频 | "当地政府承诺加强消防安全管理" |
| 原因空白 | 正文过短或信息密度不足 | **最大类(53/92)** | 字数 < 1500 字，无需理由即可判删 |

**空白原因的定义**（论文可引用）：人类标注者将"未填写原因的直接去除"统一视为"信息密度不足"的代理信号。这使得"去除"标签同时编码了"无重建细节"与"信息稀薄"两层含义。

## 四、AI 启发式自动筛选（Stage B）

### 4.1 协议设计：保守自动剔除 + 不确定性路由

从金标准归纳出关键词启发式规则，核心设计决策有三：

1. **保守自动剔除**：AI 只在对"去除"高置信时自动落定，**永不自动保留**。因保留集对下游 VR 重建价值最高，误留代价 >> 误删代价，故把不确定性全部导向人工。
2. **不确定性路由**：AI 只把"疑似可保留"的条目路由给人类，等价于主动学习中的 uncertainty sampling。
3. **金标准可解释**：每条人类标注都带 `原因` 文本，使启发式可被审计、可被迭代。

### 4.2 判定规则（Python 伪代码）

```python
def predict(text, meta):
    L = len(text)
    if L < 200:                    return '剔除', '正文缺失/过短', '高'
    if irrelevant_by_url(meta):    return '剔除', '完全无关', '中'
    if L < 600:                    return '剔除', '字数/细节不足', '高'
    
    scene_words = extract_embodied_scene_words(text)  # 见 5.1
    proc_words = extract_procedure_words(text)
    score = len(scene_words)
    ratio = score / (score + len(proc_words) + 1)
    
    if score >= 4 and ratio >= 0.25:
        return '待复核', '含若干具身场景细节', '低'
    return '剔除', '缺具身场景细节', '中'
```

**核心创新**：ratio 的设计——单纯 scene word 数量会被长文本虚高，引入 process word（过程报道词）作为分母可以有效区分"有场景的报道"和"有过程的报道"。

### 4.3 交叉验证结果（103 条金标准）

| 人类 \ AI | 剔除 0 | 待复核 0.5 |
|:---|---:|---:|
| **剔除 0** (92) | 35 ✅ | 57 |
| **半保留 0.5** (3) | 1 ❌ | 2 ✅ |
| **保留 1** (8) | 0 | 8 ✅ |

- **误留（false-retention）**：0（保留集零污染）
- **误删（false-drop）**：1/103 = 0.97%
- 自动剔除率：35/92 = 38%（其余 62% 路由人工）

## 五、精筛规则引擎（Stage C）

### 5.1 具身场景词表（可迁移）

通过分析 103 条金标准中保留/剔除的正文差异，归纳出具身场景词表。这些词在不同领域间是可迁移的：

| 类别 | 示例词 | 权重 | 说明 |
|:---|:---|:---:|:---|
| 空间细节 | stairwell, corridor, balcony, 楼梯, 走廊, 窗框 | 2 | 空间可重建性的核心 |
| 烟雾/感知 | thick smoke, choking, 浓烟, 能见度, 呛 | 2 | 感官体验基础 |
| 身体动作 | crawling, crawl, 匍匐, 摸索, 扶着墙 | 2 | 具身体验基础 |
| 情感/心理 | panic, screaming, terrified, 恐慌, 绝望 | 1 | 情感共情基础 |
| 弱势群体 | wheelchair, deaf, blind, 轮椅, 听障, 老人 | 3 | 项目核心关注 |
| 被困/决策 | trapped, locked, jammed, 被困, 困在 | 2 | 能动性/决策点 |
| 第一人称 | "我"、"I"、"my"、"my" | 2 | 用户看重的叙事质量 |
| 叙事时间 | 分钟后, 突然, 随后, 最终, when suddenly | 1 | 叙事完整性信号 |

### 5.2 标题事件模式匹配（解决主题不相关）

标题检查正则表达式（论文期刊格式）：

```
Pattern group 1: (fire|blaze) + (tears|rips|sweeps|engulfs|erupts|rages) +
                 (through|at|in|across) + (apartment|tower|highrise|residential|condo)
Pattern group 2: (apartment|tower|highrise|residential) + (building)? + (fire|blaze)
Pattern group 3: (fire|blaze) + (at|in) + (apartment|tower|highrise|residential)
Pattern group 4: (massive|major|deadly|fatal) + (fire|blaze) + (at|in|sweeps|engulfs)
Pattern group 5: (resident|displaced|evacuat|firefighter|trap) + ... + (fire|blaze) + ... + (apartment|tower)
Pattern group 6: (kill|die|death|dead|injur|fatalit) + ... + (fire|blaze) + ... + (apartment|tower)
```

排除模式：
- 战争: missile, drone, airstrike, iran, israel, ukraine, russia
- 行业: fire department, fire chief, fire truck, fire safety, fire code
- 房价: rent, affordable, housing market, real estate
- 政治: trump, biden, election, campaign, vote, senator
- 娱乐: review, trailer, game, movie, tv show, interview
- 体育: nfl, nba, mlb, soccer, football, basketball
- 中文: 政府工作报告, 隐患排查, 消防检查, 消防演练

### 5.3 整体评分公式

```
Score = sum(embodied_scene_words * weights) 
      + first_person_bonus(paragraphs_with_我 × 2, capped at 10)
      + length_bonus(L > 2000: +1; L > 4000: +2; L > 6000: +2)
```

判定阈值：
- **候选保留**（Score ≥ 5 + L ≥ 1500）or（Score ≥ 3 + L ≥ 3000）
- **待复核**（Score ≥ 2）or（L ≥ 2500，即使 Score = 0）
- **剔除**：其余

## 七、可迁移性说明

本方法的通用性体现在三个层面：

1. **筛选原则通用**：任何需要从大规模语料中提取叙事素材的任务都可以使用"具身场景可重建性"作为标准——只需替换领域专属的场景词表
2. **协议通用**："保守自动剔除 + 不确定性路由"的 human-in-the-loop 协议不依赖具体内容领域，可直接迁移
3. **规则可替换**：标题模式匹配、词表、权重均可根据新领域调整，核心框架不变

### 迁移到其他领域的步骤

1. 定义该领域对应的"场景词"（什么内容细节是可再现场景的关键？）
2. 定义该领域对应的"过程词"（什么内容是过程报道而非场景描写？）
3. 构建 100-200 条金标准，标注保留/剔除
4. 从金标准推导出关键词启发式比率阈值
5. 应用保守自动剔除 + 不确定性路由协议
6. 人工只复核边界案例
