# 多模型打标 提示词 v2（三组拆分版）

## 为什么拆成三组

2026 年 Medical Teacher 的三模型对照研究（Rush et al., 2026, DOI 10.1080/0142159X.2026.2721362）发现两件事直接影响本项目的做法：

1. **顺序逐条编码**的一致性接近人工（β=−0.14, p=0.326）；**批量处理**（一次给多条）显著更差（β=−0.41, p=0.007），批次方差 30.16。→ 必须一条一条调，不要把 10 条塞进一次请求。
2. 模型间一致性 κ=0.750–0.755，高于人工间 κ=0.422；但模型与人工共识的一致性只有 0.42–0.53。→ 模型间一致性高不等于对，仍需人工抽检锚定。

另一项多智能体编码研究（Kim & Mitchell, 2025, arXiv:2609.11109）发现**编码表越长，准确率越低**。所以原先把 15 个字段塞进一次调用是错的，拆成三组，每组 5–6 个字段。

## 共同约束（三组都要带）

```
你是建筑火灾新闻的系统编码员。只依据给出的正文，不补充外部知识，不做因果推断。
每个非「未报告」的判定必须附一句正文逐字摘录（≤30 字），摘不出就填「未报告」。
不确定时 confidence 填 low，不要为了避免空值强行赋值。
只输出 JSON，不要解释。
```

## 调用方式

| 项 | 设定 |
|---|---|
| 每次请求 | 1 条新闻、1 个组 |
| temperature | 0 |
| 正文长度 | 统一截断 2000 字，三模型一致 |
| 调用总量 | 60 事件 × 3 组 × 3 模型 = 540 次 |
| 存放 | 三个模型的结果分别落 `结果_模型A.jsonl` / `_B` / `_C`，一行一条 |
| 禁止 | 一次请求放多条；三模型互相看到对方结果；把三组塞回一次调用 |

## 合并规则

1. 三模型一致 → 直接采。
2. 两票一致 → 采多数，标 `disputed=1`。
3. 三票全异 → 进裁决队列，裁决只看正文与三份证据句，输出最终值与理由。
4. 所有 `confidence=low` 的格子，无论票型，一律进人工抽检池。
