# AI 打标提示词 v3（五组）

配套文件：`资料包_v3/轴定义卡_v2.3.md`、`输入包_60切片_v3.csv`

---

## 怎么用（三句话）

1. **组 A / B / C 是标注**，每条新闻单独调一次，一条一条来，禁止一次塞多条（批量会显著降低一致性，Rush et al. 2026, β=−0.41, p=0.007）。
2. **组 D / E 是审查**，整份只跑一次，用来验证设计空间和 codebook 本身站不站得住，不出标注结果。
3. 三个模型的输出各自保存为 `结果_模型X.jsonl`，一行一条，不要合并后再存。

---

## 组 A · 机制码（Findings 层，5 字段）

```
你是建筑火灾新闻的系统编码员。只依据下面给出的正文，不补充外部知识，不做因果推断。

为这条新闻填写 5 个字段，取值只能是 有 / 无 / 未报告。

d1_cue_to_confirmation｜线索确认链：报道是否呈现「最初线索 → 当事人如何理解 → 是否被纠正」的一步步过程。
  有：写清了线索是什么、当事人当时怎么想、后来怎么改变判断。
  无：只给结论（"发现起火后逃生"），不给判断过程。

d2_dynamic_action_space｜可行动空间是否随火势、烟、构件或设施状态改变。
  有：同一篇里路径从可用变为不可用（或反之），且写明了变化时点。
  无：路径状态始终一致，或完全没写。

d3_social_information_mediation｜危险信息是否经他人或社会网络到达当事人。
  有：邻居敲门、家人电话、楼栋群、保安通知、朋友短信等。
  无：当事人自行感知，无他人中介。

d4_social_action_scaffolding｜他人是否使原本不可行的动作变得可行。
  有：背负、抬轮椅、架梯、带路、搀扶、破门、远程指导操作。
  无：所有动作由当事人独立完成。

d5_multimodal_substitution｜一个通道失效后是否靠另一通道补偿。
  有：听不到警报→闻到烟；看不见烟→摸门把手温度；喊声替代广播。
  无：单一通道贯穿全程，或未提及替代。

强制规则：
- 每个非「未报告」判定必须附一句正文逐字摘录（≤30 字），摘不出就填「未报告」。
- confidence 填 high / medium / low；证据薄弱时填 low，不要为了避免空值强行赋值。
- 只输出 JSON，不要解释，不要加代码块标记。

输出：
{"id":"<切片ID>","d1":"有","d2":"无","d3":"未报告","d4":"有","d5":"无","evidence":["原文句1","原文句2"],"confidence":"high"}

待编码：
切片ID：<<<ID>>>
标题：<<<TITLE>>>
正文：
<<<TEXT>>>
```

## 组 B · 设计空间六轴（Discussion 层，6 轴 + 2 个诊断字段）

> 使用前把 `轴定义卡_v2.3.md` 全文附在提示词后面，或直接把轴表贴进 [轴表] 位置。**必须贴，模型不知道 A3 是什么。**

```
你是建筑火灾场景的设计研究员。任务不是总结新闻，而是把这个事件定位到一个六轴设计空间的坐标上。

[轴表]
（此处粘贴 轴定义卡_v2.3.md 中的 A–F 六轴表，含取值与判定线）

判定规则：
1. 只依据正文。正文没写 → 该轴填 "未报告"。
2. 每轴可多选，输出数组，第一个元素是主主体处境。
3. 每个非「未报告」取值必须附一句正文逐字摘录（≤30 字）。
4. 【重要】如果正文里有内容确实装不进任何一个取值，不要硬塞。
   在 off_axis 填 "有"，并在 off_axis_note 里用一句话写清装不进的是什么。
   off_axis 是本轮验证的核心指标，如实填比填满更有价值。
5. 不要因为「看起来该有」就补一个取值。宁可留空。

输出（严格 JSON，不要代码块标记）：
{"id":"<切片ID>","a":["A3"],"b":["B2"],"c":["C5","C6"],"d":["D3"],"e":["E4"],"f":["F2","F8"],
 "evidence":["原文句1","原文句2","原文句3"],
 "off_axis":"无","off_axis_note":"",
 "confidence":{"a":"high","b":"medium","c":"high","d":"low","e":"medium","f":"high"}}

待编码：
切片ID：<<<ID>>>
标题：<<<TITLE>>>
正文：
<<<TEXT>>>
```

## 组 C · 叙事维度（`Design Space (1).md` 第一遍，5 字段）

```
你是新闻叙事分析员。只依据正文，填写 5 个叙事字段。

p1_person｜语法人称：第一人称（大量 "I / we"、当事人自述） / 第三人称（记者转述） / 混合
p2_voice｜内容立场：幸存者第一人称 / 目击者·邻居 / 救援者 / 家属·亲友 / 官方·媒体全知 / 混合多视角
p3_structure｜时间结构：线性 / 倒叙 / 多线并置 / 时间戳分段
p4_granularity｜叙事颗粒度：逐句可重建（能按句还原动作与空间状态） / 段落级（有大段描述但缺动作序列） / 只有结论（仅伤亡与处置结果）
p5_emotion｜情感标签（可多选）：恐惧 / 麻木 / 愤怒 / 感激 / 无助 / 无情感标记

规则：p5 只标正文中明确表达的情绪，不推断。
只输出 JSON。

{"id":"<切片ID>","p1":"第三人称","p2":"幸存者第一人称","p3":"时间戳分段","p4":"逐句可重建","p5":["恐惧","无助"]}
```

## 组 D · 设计空间审查（整份只跑一次，不出标注）

> 目的：让模型当方法学审稿人，检查六轴本身是否成立。这是"验证设计空间"的核心一步，比多标 60 条更有价值。

```
你是 CHI 会议的设计研究方法审稿人。下面是一份六轴设计空间的定义，以及 6 个真实案例的落点。

请只回答四件事，逐条给判断和理由：

1. 正交性：任意两轴之间是否存在概念重叠，使同一事实被迫同时改变两轴的取值？
   逐个轴对检查（共 15 对），列出有问题的轴对，说明重叠在哪。

2. 穷尽性：6 个案例中是否有内容装不进任何取值？如果有，缺的是哪一类？
   我已在标注中预留 off_axis 字段，请判断这个缺口是定义问题还是轴本身缺一维。

3. 可区分性：相邻取值之间是否能被同一段正文稳定区分？
   重点检查：A3 vs A4 vs A5；C3 vs C4 vs C5 vs C6；E4 vs E5；D2 vs D3。
   对每一组，给一个「两个标注者会分歧」的具体情形。

4. 主次规则：多选时"第一个为主主体"的规则，在本批案例中是否足以消除歧义？
   举一个反例说明它不够用的地方。

输出格式：四段，每段先用一句话给结论，再列证据。不要写成鼓励性评语，直接指出问题。

[附：轴定义卡全文]
[附：6 个案例的正文与人工落点]
```

**选哪 6 个案例**：宏福苑 Ng（B1/B5 边界）、迪拜 Marina Pinnacle（A5 + C5 + E4）、德里 Dwarka（C6 + D5）、马德里 Torre Moeve（A1 + C1 + D1，对照组）、新加坡 Chai Chee（C3 + F4 + D4 边界）、约翰内斯堡 Usindiso（C4 + B5）。这 6 个覆盖了全部易混轴对。

## 组 E · Codebook 审查（整份只跑一次）

```
你是定性研究编码手册的审稿人。下面是 5 个机制码的定义，以及 3 段新闻原文。

请回答：

1. 互斥性：d1 与 d3 是否会被同一段文字同时触发？（"邻居敲门告诉我着火了"既是线索确认链，也是社会信息中介）
   如果会，说明两者的判定边界应该怎么划。

2. 与设计空间是否重复：d2「可行动空间随状态改变」与六轴的 C 轴「可行动集」是否在测同一件事？
   d5「多模态替代」与 A 轴「信息可达性」是否重复？
   如果有重复，建议保留哪一个、砍掉哪一个，说明理由。

3. 判定线缺口：这 5 个码里，哪一个最可能出现「两个标注者给出不同答案」？
   给出一个具体的歧义句，并说明手册里该补什么规则。

4. 字段数：5 个码是否还能再砍？砍到 3 个会损失什么？

输出：四段，每段先结论后理由。直接指出问题，不要客套。

[附：codebook 5 码定义]
[附：3 段原文]
```

## 一致性判定标准（结果回来后怎么读）

| 指标 | 计算方式 | 通过线 | 不通过怎么办 |
|---|---|---|---|
| 轴内 κ | 三模型两两 Cohen's κ，每轴各算 | ≥0.6 可进论文；0.4–0.6 需补判定线；<0.4 判为不可操作 | 改定义，不改数据 |
| 完全一致率 | 三模型取值集合完全相同的事件占比 | ≥70% | 检查是否有一轴拖累，单独回改 |
| off_axis 率 | off_axis="有" 的切片占比 | ≤15% | >15% 说明轴不穷尽，v2.4 加档（首选 B6 身体换取） |
| 人机一致率 | 研究者独立编码 12 条 vs 三模型多数 | ≥85% 该字段才允许模型单独承担 | <70% 该字段回到人工 |

**注意**：κ 高只说明模型彼此同源，不等于判断正确。人机一致率是唯一的正确性锚点，不能省。
