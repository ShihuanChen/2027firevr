## 3　编码方案

- 六轴 34 档的判定线逐档给正例与反例，含 9 条「易混判定线」（L1–L10）。
- 四条铁律：一个字段只判正文可见内容；推断不算；空缺与「未报告」必须分列（v4.1 新增 8.1b）；六轴全空必须判失败重跑。
- 固定判定顺序：先 a–f 再 d1–d5。理由是骨架先于关节，减少"为了用上某机制而硬套轴"。
- a 轴 v4.2 改两步：第一步问有没有信号到达（无 → A5），第二步只问来源数（1 → A2，≥2 → A1）。判定顺序固定，不给并列选择。
- d5 v4.2 改封闭三清单：视→听、听→视、行动→被搬。定义里删掉「社会通道」——原措辞把「邻居告知」「消防员救人」都装进 d5，而那是 b 轴与 e 轴的地盘。
- d1 v4.2 加主体限定（只算当事人的认知过程，官方调查结论不算）并拆 d1a（有无线索）/ d1b（是否被纠正）。

## 4　编码执行：LLM 作为编码者（本节是最需要审的设计选择）

| 项 | 设定 |
|---|---|
| 编码者数 | 3（计划），实际 2 |
| 模型 | Claude Opus 5、Sonnet 5.5、Haiku 4.5（同厂三个能力档） |
| 温度 | 0 |
| 请求粒度 | 一篇一次请求，模型之间互不可见，不共享中间结果 |
| 提示词 | 单条提示词 v4.2，含全部 34 档判定线、易混线、输出 JSON schema |
| 结构校验 | 六轴全空且 off_axis ≠「有」→ 判失败重跑，不允许空值进结果；档位不在枚举内 → 丢弃重跑 |
| 落盘 | 每次记录 model / prompt_ver / usage / 原始返回 / invalid 字段，任一条可回溯 |

**为什么用 LLM 而不是人类编码者**：34 档 × 106 篇 = 3,604 个判定，人工双编码不现实。用 LLM 能把「判定线是否可操作」这件事测出来——如果两个独立模型在同一提示词下都收敛不了，提示词一定有问题，这个诊断价值与人类编码者相同。

**必须承认的效度威胁**：同厂三个档共享训练分布，它们之间的一致有一部分来自共享先验，不是来自判定线本身。所以现在的 κ 只能解释为「同一提示词在同族模型上的可复现性」，不能解释为「人类编码者信度」。跨厂商锚点只有 DeepSeek 的旧 60 条，且那份数据字段空缺 30–75%，已作废。

**唯一的更正性证据**是 12 条人工抽检（人机对照），尚未执行。κ 回答「会不会一样」，人工抽检回答「对不对」，两件事不能互相替代。

## 5　一致性统计

| 项 | 设定 |
|---|---|
| 两编码者 | Cohen's κ（各自边际），字段级与档级同一口径 |
| 三编码者 | Fleiss' κ（合并边际） |
| 逐档 | 每档视为二分类（标了 / 没标），二分类 κ 或 Fleiss |
| 极端边际 | 同时报 PABAK = 2Po − 1，以 PABAK 为主判据 |
| 置信区间 | 簇级 bootstrap，1,000 次，重采样单位是**事件**不是切片 |
| 轴级汇总 | 轴内各档 κ 的算术平均（跳过 nan） |

以 PABAK 为主判据的理由：34 档里有 14 档命中篇数 < 10，κ 在极端边际下会被压到很低（例：E5 命中 1 篇，κ = 0 但 PABAK = 0.974；A3 命中 8 篇，κ 0.190 但 PABAK 0.821）。只看 κ 会把这些档误判为不可靠。

**一处已修正的口径错误**：上一版逐字段统计把 2 个模型也送进 Fleiss 公式（Pe 用合并边际），导致 κ 系统性偏低。改为 Cohen 后：d1 0.155 → 0.251、d5 −0.059 → 0.121、p4 0.263 → 0.291。档级与轴级原本就走 Cohen 分支，数值不变。这项修正已写入 `15_一致性初跑_78条.md` 第 4 节第四小节。

## 6　结果（当前全部数字）

### 6.1 覆盖

- 34 档中 26 档 ≥ 3 例、7 档 1–2 例（A3、C2、D2、E4、E5、F5、F7）、1 档为空（F6 听障）。
- 六轴之外 12 篇，**11.3%**。
- 主要分布：A2+A5 = 62 篇（58.5%）、C6 = 32、E2 = 40、D1 = 34、D5 = 19。

### 6.2 一致性（106 篇切片，103 起独立事件，3 个独立编码者，v4.2 判定线）

> 本节数字已于 2026-10-23 用 106 篇 × 3 编码者重跑后更新，取代原 78 条双模型（v4.1）结果。原始 v4.1 数字保留在本节末供对照。

轴级（Fleiss' κ）：

| 轴 | 档均 κ | 档均 PABAK | v4.1 双模型对照 |
|---|---|---|---|
| f 处境主体 | 0.709 | 0.895 | 0.788 |
| d 决策指向 | 0.669 | 0.814 | 0.716 |
| b 确认的社会性 | 0.585 | 0.814 | 0.495 |
| c 可行动集 | 0.572 | 0.790 | 0.509 |
| a 信息可达性 | 0.497 | 0.781 | 0.397 |
| e 能动性来源 | 0.342 | 0.778 | 0.513 |

字段级（Fleiss）：p1 0.219、p2 0.468、p3 0.520、p4 0.565、d1 0.656、d1b 0.692、d2 0.421、d3 0.476、d4 0.485、d5 0.399。

**v4.2 三处改法的效果已验证**：d1 0.251 → 0.656（加主体限定 + 拆 d1b）、d5 0.121 → 0.399（封闭三清单）、a 轴 A2 档 0.084 → 0.544（固定两步判定）。这三条确认了 6.3 节的判断。

**本轮新发现（回应本文 §0 第 1、3 问）**：把每个编码者给的多选数组按位置拆开，首位为主档、其余为附档——主档分歧 28.2%，附档 51.8%，差 1.84 倍。e 轴 κ 0.342 因此不是「判不准」，而是 codebook 规定了「首个是主」却没规定「什么时候允许多选」。这是唯一一处靠读规则文本就能定位、不需重跑语料即可修的问题，修订方向是给每个轴补「并存准入线」。

**口径限制（必须一起说）**：三个编码者同属一个模型族（两个通用档实例 + 一个推理档），测的是族内稳定性而非跨厂商信度；且本项目无人工金标准，κ 只支撑「判定方案可重复」，不支撑「标注正确」。

**原 78 条双模型（v4.1 判定线）数字，保留供对照**：轴级 Cohen's κ：a 0.397、b 0.495、c 0.509、d 0.716、e 0.513、f 0.788。字段级：p1 0.481、p2 0.446、p3 0.462、p4 0.291、d1 0.251、d1b n/a（v4.1 无该字段）、d2 0.525、d3 0.657、d4 0.566、d5 0.121。κ < 0.4 的档共 8 个：A1 0.344、A2 0.084、A3 0.190、B5 0.361、C2 0.361、C6 0.369、E5 0.000、F1 0.319。其中 PABAK 也 < 0.4 的只有两个：**A2 −0.051**（47 篇）与 **F1 0.308**（65 篇）。其余六档属于极端边际。

### 6.3 从一致性推出的判断

- a 轴最弱，根因是 A2 要求编码者先穷举全部通道再判断哪些失效，而报道极少给出完整清单 → 改为两步判定（v4.2）。
- d5 最弱的根因是定义污染（含「社会通道」）→ 改为封闭三清单（v4.2）。**注意：d5 曾以「κ 为负」为论据，该论据在口径修正后撤回；结论改由 8 条分歧的证据句内容支撑（7 条是敲门通知、走消防梯、消防员救人、挥衣物求救、抱猫逃生）。**
- d1 弱有两个原因：主体未限定、认知环节是否必需 → 加主体限定并拆分（v4.2）。
- F6（听障）为零是媒介空缺：在 1,053 个未入集事件里全量扫描，视障命中 0、听障命中 0。写作时按「发现」处理，不列进 limitation 的缺陷栏。
