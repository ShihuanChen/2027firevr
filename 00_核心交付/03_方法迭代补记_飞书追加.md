### 5.2 第 14 轮：把"篇"改成"事件"来计数

原先按篇统计，得出 60 个事件组（evg）。逐条核对后发现 <span background-color="light-yellow">60 个 evg 只对应 25 起真实火灾</span>：宏福苑 20 个 evg / 45 篇、纽约 Bronx 17 个 evg / 39 篇，两簇占 122 篇的 69%。以篇为单位的分布因此是失真的。

同时把 26 类细节拆成三层：过程类 20 类（能重建逃生序列）、元数据 2 类（时间、主体属性）、非过程 5 类（伤亡、听证、情绪、政策、官方指令）。由此得到通稿判据：<span background-color="light-yellow">过程类 ≤ 2 且非过程类 ≥ 4 判为通稿碎片</span>。

重筛结果：60 切片 → 51 切片，独立事件 25 → 47，篇数 122 → 69，单事件篇数 4.9 → 1.5。

### 5.3 第 15 轮：脚本全量补搜为什么失败

做法：22 条宽查询 × 6 语种，GDELT DOC API 与 Google News RSS 双源，五道门槛（正文长度、火灾判定、场景词、人物动作、去重）。

结果：原始约 1000 条 → 过全部门槛仅 2 条，<span background-color="light-yellow">合格率 0.2%，新增细节类型 0</span>。

结论记入方法：**宽查询不产出可重建细节，因为缺的不是检索词，是报道体裁。** 通稿、快讯、调查报道都不写逃生过程，能写的只有当事人访谈与特稿，这类文本在索引里本来就不多。此结论直接改变了第 16 轮的策略：从"铺量检索"改为"按缺口逐一构造查询"。

同一轮还修掉两个工具层障碍，均写入脚本注释：GDELT DOC API 全程 429（IP 限流），实际只能靠 Google News；Google News RSS 给出的 link 是跳转页，必须先经 `gnews_decode.py`（data-n-a-sg/ts + batchexecute garturlreq）还原出版商 URL，否则抓到的全是汇总页。

### 5.4 第 16 轮：编码集扩容 51 → 94

三项校验先做，再补搜：

1. <span background-color="light-yellow">输入包与编码集错配</span>：旧输入包 96 行里有 30 条是上一轮已删的通稿碎片，另有 21 起已入集事件从未进入输入包。此前报告的"D4 = 0"由此判定为假空缺。
2. 全库扫描 F5/F6：1053 个未入集事件中视障、听障命中均为 0。
3. 定向补搜：51 条查询（7 个缺口轴 × 多语种 + 12 条质量查询）→ 原始 558 → 解码与抓取淘汰 126 → 正文过门槛 70 → 逐条看证据句后保留 26 事件 / 28 切片。

扩容结果：事件 51 → <span background-color="light-yellow">94</span>，切片 69 → 96，主分析（过程细节 ≥ 3 类）60，补充层 34。缺口补齐情况：D4 0 → 4，E3 0 → 2，E5 0 → 1，F5 0 → 2，F8 → 5；F6 仍为 0，当时判为体裁空缺。

**这轮暴露的方法问题**：以关键词判定"是否含过程细节"会把科普段落里的"应该往下跑"算成事实编码。第一次 34 档粗筛因此把所有档都撑满了，逐条核证后大量虚高。结论：关键词只能用来找候选，不能用来定档。

### 5.5 设计空间的三次重构

| 版本 | 结构 | 问题 |
|---|---|---|
| v1 | <span background-color="medium-gray">44 字段</span>（叙事视角、叙事结构、颗粒度、核心冲突、情感标签、身体主体、感官主导、交互六件套、六角色对接、氛围叙事机制、VR 可模拟性、场景特征、SAVTBC、场景总分） | 一半字段是设计参数而非现象观察；无判定线，无法算一致性，也无法交给第二编码者 |
| v2 | 5 维（视角、叙事视角、结构、可模拟性、颗粒度、情感）+ E1 + 两机制 | 维度不同层；机制是清单，永远开不完 |
| v3 | <span background-color="light-yellow">六轴 34 档</span>（a 信息可达性 5、b 确认的社会性 5、c 可行动集 6、d 决策指向 5、e 能动性来源 5、f 处境主体 8） | 每档状态有限且互斥，可算穷尽性；E 层退出编码层，改为由 a–f 组合推导 |

关键判断有两层：

1. v2 与 v3 不是替代关系，是**两层**。v2 回答"这条新闻写了什么、能否在头显重建"（素材筛选层），v3 回答"重建出的场景落在设计空间哪一格"（设计与分析层）。汇报时并列展示，不合并。
2. v1 到 v3 不是"改字段"，是**拆层**。v1 把现象（新闻里能观察到的）与设计参数（你打算让 VR 里发生什么）混在一张表里，所以既无法复现也无法验证。v3 只让现象层进编码，机制层做分析，设计参数层靠查表推导。

### 5.7 双模型一致性与 PABAK（60 条 × 2 模型，2026-10-22）

逐字段 Cohen's κ，bootstrap 1000 次给 95% CI。

| 字段 | κ | 95% CI | 判读 |
|---|---|---|---|
| p4 颗粒度 | 0.700 | [0.51, 0.87] | 可写进论文 |
| d2 动态空间 | 0.669 | [0.38, 0.90] | 可写进论文 |
| p5、p2、d4、d3 | 0.60 / 0.53 / 0.55 / 0.49 | 均跨 0.3 以上 | 中间，需复核 |
| p3、p1 | 0.463 / 0.445 | [0.17, 0.71] / [0.25, 0.62] | 中等偏低 |
| <span background-color="light-yellow">d1、d5</span> | 0.302 / 0.227 | [0.10, 0.51] / [0.00, 0.65] | 判定线必须改 |
| <span background-color="light-yellow">confidence</span> | 0.038 | [−0.07, 0.16] | 不可用，必须重定义 |

六轴档均 κ：d 0.753、b 0.593、f 0.570、a 0.546、e 0.507、c 0.373。整体分歧格 277/1080 = 25.6%。

**这一轮最重要的方法学发现**：逐档 κ 出现五个 0.000，看似完全不一致，实际相反。

| 档 | κ | 一致率 | PABAK | 实情 |
|---|---|---|---|---|
| C1 | 0.000 | 88.3% | 0.767 | 两模型几乎都标了 |
| C6 | 0.000 | 95.0% | 0.900 | 同上 |
| E4 | 0.000 | 98.3% | 0.967 | 两模型几乎都不标 |
| E5 | 0.000 | 98.3% | 0.967 | 同上 |
| F8 | 0.000 | 96.7% | 0.933 | 同上 |

这是 prevalence problem。**处理办法写死为规范：六轴逐档一致性一律同时报 κ 与 PABAK（2Po−1），以 PABAK 为主。** 只报 κ 会得出"这套轴不可靠"的错误结论，而实际只是某档在样本里几乎全有或全无。

四条改线（已写入 Codebook v4.1 第 7 节）：d1 拆成"线索驱动"与"误判后纠正"两档；d5 按来源拆成自察型与告知型；confidence 改三条硬判据、取消 medium；c 轴定死判定顺序（能否走通 → 走进去会不会死 → 总数是否为零）。**改线后用同一批数据重跑，不回溯修改已产出的判定值。**

### 5.9 第 17 轮：把轴和判定线都验一遍

这轮做三件事，均为验证而非产出。

**一、六轴全量标注**。96 条切片逐条标 a–f 六轴，得到覆盖表：充足（≥3 例）21 档、单点（1–2 例）10 档、空档 3 档。空档是 E4（等通知）、E5（错误指令）、F6（听障）。off_axis 12 条，占 12.5%，低于 15% 阈值。

标注过程中发现的关键事实：<span background-color="light-yellow">A2（单通道）36 条 + A5（无信号）19 条 = 55 条，占 57%</span>。语料里的火灾绝大多数是"只拿到一条线索"或"什么也没拿到"。这决定了 VR 的主场景是信息稀缺下的判断，不是信息丰富下的决策。

**二、判定线压力测试**。用双模型逐档 κ + PABAK 定位失效点，同时检验八条易混线：六条直接可用，两条（独居 ≠ 是否获助、打电话 ≠ 被指导）需补一句限定。

**三、第三轮定向补搜（F6 专项）**。32 条查询 × 10 语种，原始 182 条，F6 占 57 条，过正文门槛 0 条。逐条读正文后确认两条实质案例：亚利桑那 82 岁聋人 Cynthia Minter（无闪光警报，死于床边）、马来西亚 81 岁聋哑 Noriah Mat Desa（弟弟逃出，她死在客厅）。两条均为独立住宅，不进主编码集，作补充证据。

<span background-color="light-yellow">F6 的结论因此改写</span>：不是搜不到，是搜到了也只有结局。57 条候选中死亡通报 12、消防科普 15、邻居证人 8、调查司法 10，有当事人过程的仅 2 条。现有火灾新闻对听障者的再现集中在"死亡结果"与"技术建议"两端，中间整段省略。这段被省略的过程正是 VR 要补的东西。F6 从 limitation 的缺陷栏移入发现栏。

### 5.10 待老师裁决

1. 编码集篇数未达 100–120 理论区间（实际 96 篇 / 94 事件）。91% 的事件只有 1 篇可重建报道，硬凑到 120 篇只能靠同事件通稿灌水。建议事件数优先。
2. 是否引入第二名编码者做 12 条人工对照。现有 κ 全部是"模型之间"的一致，不能替代"模型对不对"。
3. F6 按"媒介空缺 + 两条补充实证"处理（本文件 5.9 已给出写法定稿），还是另立一节展开设计需求推导。
4. 四条改线（d1、d5、confidence、c 轴顺序）改完后，是否用改后的版本重跑全部 96 条，还是只对低 κ 字段局部重跑。前者干净但成本翻倍，后者省钱但两套判定值并存。
